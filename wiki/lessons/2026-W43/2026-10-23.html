1monorepo

/ˈmɒnəʊˌriːpəʊ/ · noun (đếm được)
IT

một repo chứa nhiều projectweb, admin, SDK… nằm chung một kho code, chung một lần commit, chung CI

ENA single git repository that holds several projects or packages which used to live in repositories of their own. → Một repo git duy nhất chứa nhiều project hay nhiều package mà trước đây mỗi cái nằm ở một repo riêng.

GHI CHÚTrái nghĩa là polyrepo / multi-repo (mỗi project một repo). Không đồng nghĩa với monolith: monorepo nói về chỗ chứa code, monolith nói về chỗ chạy — một monorepo hoàn toàn có thể chứa hai chục microservice. Nhắc tới nó là nhắc tới cái giá đi kèm: CI phải biết chỉ build phần nào vừa đổi.

Ví dụ
  • Since we moved both apps into a single monorepo, a breaking change in the shared UI package shows up in CI the same morning instead of three weeks later. → Từ lúc gộp cả hai app vào một monorepo, một thay đổi làm vỡ API ở package UI dùng chung là sáng đó CI đỏ luôn, chứ không phải ba tuần sau mới lòi ra.
  • The monorepo keeps our boilerplate in one place, so a new service inherits the lint and CI config on day one. → Monorepo giữ đống code khung của bọn mình ở một chỗ, nên service mới dựng lên là có sẵn cấu hình lint với CI ngay từ đầu.
Collocationmove / migrate to a monorepo · a monorepo setup · monorepo tooling · split a monorepo · in the monorepo
BẫyViết liền một chữ: monorepo, không phải "mono repo" hay "mono-repo". Đừng lẫn với monolith (xem GHI CHÚ). Trọng âm ở âm đầu /ˈmɒnəʊ-/ — đọc "MO-nô-ri-pâu", không phải "mô-NÔ".
Họ từmonorepos, mono-repo, mono repo, monorepo tooling, polyrepo, multi-repo

2code smell

/ˌkəʊd ˈsmel/ · noun (đếm được)
IT

dấu hiệu code có vấn đềchạy vẫn đúng, nhưng cách viết báo trước là chỗ này sắp sinh lỗi hoặc rất khó sửa

ENA piece of code that still works but is written in a way that warns you of a deeper problem underneath. → Một đoạn code vẫn chạy đúng, nhưng cách nó được viết ra báo trước rằng bên dưới còn một vấn đề sâu hơn.

GHI CHÚTrong code review đây là chữ nhẹ hơn "bug" — nói "this is a code smell" là nêu nghi vấn chứ không khẳng định sai, nên người nghe đỡ tự ái. Khác technical debt (đã học 20/08): technical debt là món nợ đã biết và đã chấp nhận, còn code smell là cái mùi báo rằng có thể đang có nợ.

Ví dụ
  • A function with eight boolean arguments is a code smell: it still works, but it's exactly the kind of brittle code that breaks the moment someone adds a ninth. → Một cái function tám tham số boolean là dấu hiệu có vấn đề: chạy thì vẫn chạy, nhưng đúng kiểu code dễ vỡ, ai thêm tham số thứ chín vào là sập.
  • Don't call it a bug in review — call it a code smell and ask whether the technical debt is worth paying down this sprint. → Trong review đừng gọi nó là bug, cứ gọi là dấu hiệu code có vấn đề rồi hỏi xem món nợ kỹ thuật đó có đáng trả ngay sprint này không.
Collocationa code smell · this function smells · catch a code smell in review · a design smell · the classic smell of sth
BẫyĐếm được, phải có mạo từ: that's a code smell, không nói "that's code smell". Nói this function smells thì được, nhưng không nói "this code is smelly" (nghe như code bốc mùi thật). Trong câu tiếng Việt nghiêm túc thì đừng dịch thành "mùi code" — người trong nghề chỉ nói vậy kiểu đùa.
Họ từcode smells, smell, smells, smelly, design smell, test smell, smell test

ENThe part of a contract that lists exactly what will be delivered, by when, and for how much. → Phần của hợp đồng liệt kê đúng những gì sẽ được giao, giao vào lúc nào, và với giá bao nhiêu.

4sunset

/ˈsʌnset/ · verb (cũng là noun)
Giao tiếp

ngừng hỗ trợ theo lịch hẹn trướchẹn hẳn một ngày rồi tắt cho xong — có báo trước, có đường chuyển sang cái mới

ENTo plan the end of a product, a feature or an old version, announce the date, and stop supporting it after that. → Định sẵn ngày kết thúc cho một sản phẩm, một tính năng hay một bản cũ, công bố ngày đó, rồi sau đó thì không hỗ trợ nữa.

GHI CHÚKhác deprecate (đã học 13/08): deprecate chỉ là gắn biển "đừng dùng nữa", cái cũ vẫn chạy; còn sunset là có ngày tắt thật. Trong email khách thì sunset nghe nhẹ hơn hẳn "we will shut it down" — cùng một việc, nhưng kèm lịch và kèm đường lui.

Ví dụ

  • Before we announce the sunset date, let's get buy-in from the three accounts still on the old plan. → Trước khi công bố ngày tắt, mình nên hỏi cho ba khách còn ở gói cũ đồng ý thật lòng đã.

BẫyChia động từ gấp đôi chữ t: sunsetted, sunsetting — "sunseted" là sai. Đi với date chứ không với day: the sunset date. Và sunset clause trong hợp đồng là điều khoản tự hết hiệu lực — nghĩa khác, đừng lẫn với việc tắt sản phẩm.

ENTo stop what you are doing for a few minutes so that you can rest, before carrying on. → Dừng việc đang làm vài phút để nghỉ, rồi sau đó làm tiếp.

GHI CHÚKhác chill out (25/09) và recharge (09/10): breather là quãng nghỉ ngắn, ngay giữa việc — vài phút tới một tiếng; còn hai từ kia là nghỉ cho giãn người, nạp lại sức cả buổi. Nói với đồng nghiệp thì tự nhiên; viết email cho khách thì hơi thân mật, nên dùng a short break an toàn hơn.

Mẩu đọc

Trích một RFC nội bộ: gộp ba repo lại

We're proposing one monorepo for the web client, the admin panel and the shared SDK. Three repos today means three copies of the same config and a release train nobody trusts; the auth helper that exists in all three is the clearest code smell we have. The plan is to sunset the standalone SDK repo at the end of Q1, keep its git history, and fold the remaining work into the statement of work we already signed for the platform rebuild — no new budget, no new addendum. If migration week goes badly we roll back to three repos, take a breather, and try again in the summer.
Bản dịch

Bọn mình đề xuất gộp web client, trang admin và SDK dùng chung vào một monorepo. Ba repo như hiện nay nghĩa là ba bản cấu hình y hệt nhau và một lịch release chẳng ai tin; cái auth helper nằm ở cả ba chỗ là dấu hiệu code có vấn đề rõ nhất mà bọn mình đang có. Kế hoạch là cuối quý 1 ngừng hỗ trợ cái repo SDK đứng riêng, giữ nguyên lịch sử git của nó, rồi dồn phần việc còn lại vào bản mô tả công việc đã ký cho đợt dựng lại platform — không xin thêm ngân sách, không cần phụ lục mới. Tuần chuyển đổi mà hỏng thì bọn mình lùi về ba repo như cũ, nghỉ xả hơi một lát, tới hè làm lại.

Bài tập

5 câu về từ vựng của buổi. Làm xong rồi mới mở đáp án.

  1. Điền 1 từ: "Three copies of the same date-formatting helper in three services is a classic ______ — it works today, but it won't for long."
  2. Chọn collocation đúng: "We're ______ the v1 API at the end of June." — (a) sunsetting · (b) sunseting down · (c) making sunset
  3. Dịch Việt → Anh: "Việc nào không nằm trong bản mô tả công việc thì bên em phải làm phụ lục ạ."
  4. Sửa lỗi: "After the incident call we took a breath for ten minutes, then started the postmortem."
  5. Sửa lỗi: "We moved all three projects into one mono repo last quarter, so now it is a monolith."
Đáp án
  1. code smell — "is a classic code smell": code vẫn chạy đúng, chỉ là cách viết báo trước sắp có vấn đề. Nếu nó đã sai kết quả rồi thì mới là bug.
  2. (a) sunsetting — động từ chia gấp đôi chữ t. (b) sai hai chỗ: thiếu một t và thêm down vô nghĩa; (c) không tồn tại.
  3. "Anything outside the statement of work has to go in as an addendum." — statement of work (không phải "for work"), và việc ngoài phạm vi thì đi kèm addendum (đã học 12/10).
  4. "…we took a breather for ten minutes…" — take a breath là hít một hơi; nghỉ vài phút là take a breather, có -er và đọc với âm /ð/.
  5. "We moved all three projects into one monorepo last quarter, so now it is a monolith." → sửa hai chỗ: viết liền monorepo, và câu sau sai logic — gộp repo lại không biến hệ thống thành monolith. Monorepo là chỗ chứa code, monolith là chỗ chạy.
